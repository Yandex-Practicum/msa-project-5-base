# Обоснование метрик и алертов

Цель: видеть раздельно **приёмку** складского отчёта и **прогон** Spring Batch. Смешивать их в одну «латентность загрузки» нельзя: HTTP должен быть миллисекундами, SLO 30 секунд относится к прогону на 2 000 строк.

Стек: **Prometheus** (сбор), **Grafana** (дашборды), **Alertmanager** (маршрутизация). В GCP тот же смысл можно закрыть Cloud Monitoring; для курса и постепенной миграции в микросервисы выбран OSS-стек из задания.

## Ключевые метрики

| Метрика | Откуда | Зачем |
|---|---|---|
| Длительность HTTP-приёмки | WildFly (Micrometer/Prometheus) | Регрессия «отчёт снова висит в вкладке». Не должна расти вместе с числом строк |
| Длительность прогона; длительность / 2000 строк | Spring Batch + Micrometer (`spring.batch.job`) | SLO: среднее на 2 000 строк ≤ 30 с |
| Прогоны: success / failure / running | Spring Batch | Ошибки прогона vs ошибки формата |
| Строки read / written / skipped | Spring Batch step metrics | Skip — битые строки внутри принятого файла; written — факт обновления остатков |
| Глубина очереди принятых отчётов | размер очереди (GCS notification lag / broker / таблица) | 100–150 приёмок при меньшем числе воркеров — очередь растёт, это не падение |
| Число параллельных прогонов | Batch workers / k8s replicas | Потолок воркеров vs пик приёмок |
| Ошибки GCS и PostgreSQL | клиентские метрики / Micrometer | Отличить «упал ETL» от «нет бакета / нет БД» |
| CPU и память WildFly и Batch | cAdvisor / JVM Micrometer | Старый мониторинг VM недостаточен, когда нагрузка в job, а не в VM целиком |

## Что алертим

- Ошибка **прогона** (job FAILED) — дежурному DevOps, не сотруднику склада (ему WebSocket).
- SLO прогона нарушен (p50 длительности на 2 000 строк > 30 с в течение N минут).
- Очередь принятых отчётов растёт дольше окна смены.
- Прогоны не завершаются (running застрял, нет success).

## Что не алертим

- **Ошибка формата отчёта** — штатный UX: сотрудник чинит CSV и загружает снова. Это счётчик на дашборде, не PagerDuty.
- CPU VM без привязки к прогону — то, что уже есть и не объясняет «отчёты висят».

## Дашборд (минимум)

Три ряда в Grafana: приёмка (RPS, latency, ошибки формата) → очередь и параллелизм → прогоны (duration, success ratio, rows, SLO). Корреляция с логами по `reportId`.
